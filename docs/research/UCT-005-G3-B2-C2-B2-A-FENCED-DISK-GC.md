## 1. Gap resolved and architecture

C2-A had an actual file-backed queue, mark/live bitmaps, and at most six explicitly modeled page buffers for *collection*, but no authenticated durable historical PIN authority: collector operated directly on untrusted PIN slot pages and rewrote the active bitmap before any GC publish. C2-B1 added authenticated PIN/UNPIN journal and fenced generation publication, but its GC implementation used **all-epoch reachability sets and a giant in-RAM bitmap**. Naively claiming the union established a physical bounded-RAM system would be a serious resource and security error.

The new implementation [DiskFencedGC](../../research/uct005_g3b2c2b2a_fenced_disk_gc.py) composes these existing components in one serializable, honest control actor:

1. Authenticate the PIN journal **published** tip via B1's MAC chain and independent trusted 40B PinFence; reconstruct at most C active client slots. Compare each PIN epoch and digest to the independently attested root catalog, then *write* C2-A's whole-page PIN slots derived from the authenticated prefix. Any untrusted PIN slot is overwritten before collection; never trust arbitrary slot contents as its own authority.
2. Clone the current C2-A live bitmap image-by-image to a fresh temporary-file candidate, charging every full-image read/write. Freeze the PIN tip and let C2-A run its SHA-256-checked disk queue/mark/sweep algorithm on the **candidate**, not on the active disk bitmap. Restore the active bitmap binding even after exceptions or simulated crashes. No reachable-ID union or Python N-byte bitmap is constructed in the adapter.
3. Stream the canonical candidate bitmap page-by-page through SHA256 and into immutable GC generation images (one header P-byte image + ceil(N/P) bitmap images); the generation digest commits the generation number, full published PIN fence (seq **and tag**) and all N live flags. Full-page copies, reads, writes, SHA calls and one os.fsync are separately charged.
4. Immediately before publication, validate the entire staged immutable generation against its digest and the published authenticated journal *prefix*; reject if any new PIN or UNPIN changed the fence. An independently trusted ideal atomic 48B GcFence commits generation only **after** a successful metadata flush. Restrict new historical PINs to epochs still pinned at publication and latest, forbidding post-GC resurrection.
5. After trusted GC publication, verify the complete on-disk committed generation again **before** applying any live-bit change. Apply page-level bitmap rewrites with at most P-sized buffers; any partial deletion is retryable with the same authenticated generation. A crash before publication cannot free pages. Logical TRIM counts each newly dead node-page, **not** actual SSD discard or filesystem hole punching. Physical NODE pages remain allocated on disk.

A frozen monotone latest root, a separate PIN tip, and a separate GC tip remain **three paid trust services**. Stored journal pages and GC pages alone are not anti-rollback authorities. The honest actor serializes all PIN, UNPIN, and GC commits. Byzantine disk mutation between pin-slot reconstruction and marking is not fully prevented by a cryptographic protocol here; the collector's child-link SHA verification and generation checks do **not** constitute a formal Byzantine concurrent-store reduction.

The page size is P=4096 by default; each C2-A immutable tree node occupies one full P-byte image, unlike C0's packed 25-record pages. The author/exporter and the historical attestation store **still** require O(H+n) Python memory; B1's journal replay holds O(C) client slots. The six-buffer bound is only the **GC file data-plane**, whose bitmap, queue and generation stream do not allocate in-memory O(N) pages. No end-to-end bounded-memory claim is accepted.

## 2. Conditional no-premature-reclaim invariant

Assume (A1) complete immutable B2-B authenticated DAG roots and SHA-256 binding, (A2) owner authentication key and independent authentic historical root catalog, (A3) atomic monotone durable PIN and GC control fences and single serialized actor, (A4) a modeled os.fsync ordering guarantee for complete page images, (A5) no malicious pin-slot swap during the protected mark pass, and (A6) a non-failing read/write of complete committed bitmap images or fail-closed detection.

Let V(e) be all node pages reachable from attested epoch e, P(L) the PIN epochs in committed journal tip L, A the active bitmap, and M the staged candidate computed by the exact C2-A collector from the latest root and the authenticated reconstructed pins. At the frozen L, the C2-A reachability induction shows for all v ∈ V(latest) ∪ union_{e in P(L)} V(e), M[v]=1. **Before the independent GC fence is advanced** the active bitmap A is untouched. If L changes, the stage is rejected; if the trusted generation advances, its immutable full-page bytes were flushed and digest-validated. Only afterward may A[v] change from 1 to 0, and the committed generation remains re-readable and verifiable before resuming after an idealized interruption. The post-publication PIN policy prevents accepting a future historical PIN requiring an epoch that was dropped by the committed bitmap.

This is a classical retention safety argument under explicit trusted-actor and ideal-file-barrier premises. Neither power-loss/torn-sector behavior on physical drives nor an original computational/cryptographic lower bound follows.

## 3. Independent model checks and billing

[Independent cross-model test file](../../research/test_uct005_g3b2c2b2a_fenced_disk_gc.py) compares the exact live-page set to a **separate test-only DAG BFS oracle** for exhaustive binary initial vectors n=2..5 and two historical independent PIN holders; after releasing both, only latest-reachable pages may remain. This unbounded oracle exists **only in tests**. Additional gates cover: stage PIN race, post-GC historical pin rejection, all prepublication and postpublication crash cuts, forged HMAC journal entry, forged tree root child, committed/staged bitmap corruption, invalid cut values with no active mutation, idempotent recovery, root parity reconstruction, and multiple bitmap pages for n=130.

**Recorded page-I/O ledger:** adapter source-bitmap reads, candidate-bitmap writes, journal-to-arena pin-slot writes and root reads, generation stream reads/writes, active bitmap reads/writes, metadata fsync, metadata truncate, logical trim count, 48B GC trusted anchor publications, and the B1 PIN journal's independent per-event I/O, MAC, fsync and 40B publication counts. C2-A's independently charged BFS-mark-queue + mark/live bitmap + SHA-link validation are returned in each FencedStage as collector_cost. **Do not add only adapter.cost and omit collector_cost**. The writer/source-root allocation and initial storage are charged separately by C2-A; query reference verification is O(n) and not a same-task optimized upper frontier.

Every full-page file operation is priced as P bytes **of API-level transfer**; os page cache, real SSD FTL amplification, allocation/discard, physical moved bytes, compaction/reuse, directory fsync/rename, network retries, PIN delivery and actual power-loss durability are not measured. File truncation and logical discard counts do not establish physical reclamation. Running TemporaryFile after process restart is not a production recovery protocol.

## 4. Novelty firewall / future steps

The classical mark/sweep invariant plus an independently assumed 40B PIN authority and GC CAS is a **restricted upper construction**, not a genuinely new foundational theorem. The false for-all-ranges update×query page inequality was rejected in C1. No fresh hard-query lower bound is demonstrated by this stage. Do not transplant dynamic partial-sums lower bounds (LIT-111 Fredman–Saks, LIT-112 Pătraşcu–Demaine) or computational memory checker lower bounds (LIT-157 Boyle–Komargodski–Vafa) unless every model/quantifier is preserved in a formal reduction.

**Next G3-B2-C2-B2-B:** add an actual file-backed online author SET with root COW publication, torn/barrier/root ABA and old PIN version replay checks. Price path reads, page placement/packing and source writes in one explicit I/O ledger; implement durable named root/pin state and a specified filesystem crash/recovery failure model, instead of silently treating TemporaryFile as permanent storage. Then formulate a single strict same-model worst-case / hard-query lower-bound candidate, or record STOP_NOVELTY for the hypothesized service. UCT root #105 and research #178 stay OPEN; no Rust/product.
