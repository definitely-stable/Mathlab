## 1. Model and comparison contract

APPEND_SINK adds a new vertex v with a publicly supplied parent-subset incidence row of exactly **v bits**. Parents p satisfy p<v. This row is supplied to the updater; it is never a free query-time oracle. For every append, old vertex-label page images are immutable and addressable using stable numeric IDs. Boolean query reach(u,t) includes zero-length paths (u=t). In an honest store, the two code paths must return identical answers.

Freeze a horizon cap before any insert, page bytes P>=8, fixed little-endian vertex/chain IDs of width d=max(1,ceil(log2(horizon)/8)) bytes, zero-filled last-page padding and a virtual direct page namespace. Per page request, charge **1+2d address bytes** (namespace + record ID + page index), separately from the **P transferred page bytes**. Both codecs use precisely the same key type and transfer accounting. This is a *priced request header*, not a claim to price the transport protocol, server directory, cryptographic keying, physical SSD writes, allocation or actual latency. The global horizon, decoder and page-key calculation are immutable common program information excluded from costs.

Both codecs begin with one allocated, zero/empty remote manifest page. Initialization transfer is excluded from update totals **but live initial page and its request address are counted**. Every append reads the existing remote manifest, and overwrites the new manifest, with complete pages charged for each transfer. No CAS, journal, atomicity or rollback guarantee is provided; changing current metadata is an explicitly unsafe durability model. No index caches survive across operations.

- **Dense bitmap**: immutable ancestor bits for node v, packed in ceil(v/8) bytes, stored in ceil(v/(8P)) pages (0 pages for v=0). A one-page query reads the target bitmap page if u<t. The updater reads every required source parent's bitmap page exactly once, combines its bits and the parent's self bit, then writes the new pages. The common four-byte manifest carries current vertex count.
- **Chain top**: frozen deterministic **first-compatible** chain assignment from Mathlab G0, not asserted identical to the online Felsner decomposition. Each immutable label contains a four-byte number of top entries, d bytes for the node's chain ID and sorted pairs (chain_id, top_vertex) occupying 2d bytes each. The manifest contains the four-byte vertex count, four-byte number of chains and d bytes per current chain head. The updater reads the complete parent record(s) and current manifest; chooses the first chain with head already among the new node's reachable tops, otherwise creates a chain; writes its new immutable label and the new manifest. Query u<t reads ancestor's first page for its chain ID, then **all pages of the target's chain-top label**, because this reference uses sequential decoding, not a secondary positional directory. Paper-level constant-time RAM queries must NOT be inferred as one remote page read.

**Charged independent resource vector:** parent_input_bits, update_label_page_reads/writes, update_manifest_page_reads/writes, query_page_reads, live_label_pages, live_manifest_pages, page request address bytes and a conservative per-operation workspace bound. Every page is a whole P-byte application transfer. For bitmap appends, the implementation buffers the full new record before writing; its enforced workspace envelope includes the output buffer plus two pages. Chain records and manifest are also buffered, with a conservative envelope including the largest parent/new record and chain-head table. RAM cap is checked before label/manifest writes, but unsuccessful reads can still consume resources. Python runtime and object allocator overhead, manifest atomicity, input-row staging, data-structure dictionary bookkeeping and metadata for the virtual page allocator remain **unpriced**. Consequently neither universal physical RAM feasibility nor true disk IOPS/NAND or product competitiveness follows.

## 2. Proof boundaries

**C2-C-L1: classical transitive closure invariant.** Bitmap stores all strict ancestors; union_{p in parents(v)} (ancestors(p) union {p}) computes the exact answer by induction. For the first-compatible chain algorithm, every chain's nodes are totally ordered by reachability; its entry top_v(c) is the latest ancestor of v in chain c. Hence reach(u,v) iff u<=top_v(chain_of(u)). On append, the new chain is either new, or extends a chain whose current head already reaches the appended vertex, so chain validity persists. This is classical chain-index theory; independently checked against raw-graph DFS and existing Mathlab G0, not a novelty theorem.

**C2-C-F1: page rounding defeats blanket compression implications.** Fixed width d=1 and P=16, for a 24-vertex chain, *both* index representations occupy one page for each nonempty label; the chain codec additionally stores a record for vertex zero, reads the ancestor's chain ID on a query and pays manifest reads/writes. Therefore a smaller logical O(1) top-set does not imply fewer page transfers for any trace or P.

**C2-C-F2: longer narrow chain exhibits a real storage crossover, not universal dominance.** On a 160-vertex chain and P=16, dense ancestor bitmaps occupy **190 live label pages** while first-compatible chain-top labels occupy **160**, but on three concrete nontrivial queries bitmap incurs **3** page reads and chain-top **6**. The latter also incurs a read of each source's chain label. This is *not* an asymptotic lower bound, not a benchmark, and not a free claim of superior chain query latency.

**C2-C-F3: metadata rewrite amplification on a wide antichain.** On a 160-vertex antichain and P=16, bitmap has 160 manifest-page reads and 160 writes; chain-top has **950 reads and 960 writes** as the chain-head manifest grows from one to eleven pages. The immutable label-page totals are 190 bitmap vs 160 chain, so counting only stored labels conceals heavy metadata transfers. This is a counterexample to a simplistic label-space-only preference and is workload/serialization dependent.

## 3. Reproducibility and exact source distinction

~~~bash
python research/dag002_g1c2c_page_comparator.py
python -m unittest discover -s research -p 'test_dag002_g1c2c_page_comparator.py' -v
~~~

Nine independent regressions enumerate **all 1,024 five-vertex topological DAGs** for P=8 and P=16, checking all previous and current query pairs after each append against an independent backwards DFS, immutability of every old record image, exact incidence-row charge and separately computed page/request ledgers. Further adversarial cases cover chain count, 160-vertex storage crossover, antichain manifest amplification, deterministic parent order, workspace rejection before writes, cross-serialization page boundaries, invalid parent IDs and undetected malicious page replacement. Tests use only Python stdlib and run on GitHub-hosted runners. Local tests are evidence of bounded implementation correctness, not a proof of a general lower-bound claim.

**Prior-art comparison:** [Bulteau–David–Horn–Tran-Girard, SEA 2025, *Incremental Reachability Index*](https://doi.org/10.4230/LIPIcs.SEA.2025.9) already studies immutable append-only DAG reachability indexing, using a Felsner/Jagadish design and more compact anchors. Mathlab's **first-compatible** G0 comparator is not that paper's most advanced anchor scheme and should not be presented as a verified reproduction of its bounds or experiments. Jagadish 1990 and Felsner 1997 are classical ancestors. Current comparison is an explicitly fixed reference codec, not a claim of scientific algorithmic novelty. Independent proof-level prior-art audit remains required before seeking a theorem.
