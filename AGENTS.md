# AGENTS.md — Mathlab research agent contract

Mission: verifiable original-or-classical mathematical work and reusable evidence. Efficiency means **scoped retrieval**, not skipping proof and prior-art gates. The repo is internal-first and AI-agent-friendly.

## Session read order

1. Resolve **live** main HEAD, active/open PRs, stacked dependencies and **exact-commit CI** through GitHub. [STATUS-LIVE](docs/STATUS-LIVE.md) supplies links, not frozen state. `docs/CURRENT_STATE.md` is a historical log.
2. Route by [Research Index](docs/RESEARCH-INDEX.md) and [RESEARCH-MAP.json](docs/research/RESEARCH-MAP.json). These are non-authoritative pointers, not accepted-result registers.
3. Read exact issue, most recent *accepted* document, specific claim/model, and [research chronology](docs/research/README.md). A pending PR is not accepted evidence.
4. Read [known/proved/stopped JSON](docs/research/KNOWN-AND-STOPPED-RESEARCH.json), [decisions](docs/research/DECISIONS.md) and relevant counterexamples before creating/reopening a target.
5. Check [primary-source catalog](docs/research/catalog/literature.json) and [relation registry](docs/research/catalog/registry.json). A related result requires an exact source-to-model transfer proof.
6. Inspect statement, assumptions, quantified scope, executable oracle/independent falsifier and any [Lean certificate](lean/README.md). Only then propose a narrow next slice.

## Source of truth

- Live SHA / PR / CI: GitHub itself at exact commit.
- UCT-005 theorem status: [UCT-005-THEOREM-TREE.json](docs/research/UCT-005-THEOREM-TREE.json) and accepted proof artifacts; root OPEN_UNPROVED unless separately proved.
- Prior art and reopening: [KNOWN-AND-STOPPED-RESEARCH.json](docs/research/KNOWN-AND-STOPPED-RESEARCH.json). Its Markdown is generated by [known_registry.py](research/known_registry.py).
- Literature identity and provenance: `docs/research/catalog/literature.json` and `registry.json` (not old README counters).
- Other theorem status: exact issue/PR, independently checked proof/source and accepted revision. Navigation node descriptions never override status.

## Claim/evidence policy

- Freeze exact finite/asymptotic cost model, quantifiers, parameter ranges, source assumptions and novelty boundary.
- Distinguish **known theorem**, **new scoped proof**, **finite exact computational result**, **numerical evidence**, **unverified argument**, **Lean-checked statement**, **counterexample**, **product authorization**.
- Keep failed routes and precise countermodels as first-class results. Avoid inferring global no-go from restricted cases.
- Re-run computational claims with independent checkers where possible. CI passing is not a peer-reviewed or globally correct theorem.
- No automatic production changes from research; no real-workload performance claim from synthetic tests.

## Smallest safe change

1. State base HEAD, relevant issue, upstream PR/CI and touched files. Prefer a dedicated, narrow branch.
2. Add the proof, independent falsifier/certificate, primary references, exact status and limits.
3. Run relevant GitHub-hosted checks for the **exact PR head** and record links; never assume acceptance on pending tests.
4. Update existing registries using existing generators. Update navigation only for a changed canonical entry, not per paper or PR.
5. Report: Last verified HEAD; Current milestone; Current slice; Open PR; Last CI; Acceptance; Known blockers; Next allowed action; Last updated from repository.

## Map semantics

`navigation_related` means **topic adjacency for retrieval**, not `proves`, `depends_on`, `refutes`, `implies`, or an accepted reduction. Follow only needed paths.

No compulsory agent plugins, MCP services, self-hosted runners or background workflows. Use Python standard library checks where possible.
